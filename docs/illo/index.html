Currently workingActive epics

  • CSP MasteryP22E003 — The user flow reaches Clip Studio Paint without depending on the app alone: .clip files are readable and writable, the library is the user's own and it makes sense, and agent environment and tools persist between sessions. A quick gallery of reusable backgrounds and patterns exists, and the gaps to a productive setup are named.
  • Walking SkeletonP22E007 — The project is a declared experimental tier, published on its own domain through the same exposure pattern the other experimental project uses: tunnel to localhost, no access gate, rate limit. The walking skeleton proves the essential loop — pen, pressure, vector line, file, reopen identical.
  • Math FriendlyP22E011 — Math friendly is a verifiable property, not an aspiration, and it filters which brushes, queries and filters the community can write. A feature that cannot be expressed as a function over strokes does not enter the set, and the reason is recorded.
  • 3D SketchP22E013 — Form and perspective construction is the step the two desktop tools leave open, and a sketch tool in three dimensions fills it. Each candidate either enters the user flow with a named role or is rejected with a reason, and the decision is recorded before any tool is adopted.
  • Commit BatteryP22E017 — A battery of checks runs before every commit in the project, so a commit that breaks the build or the contract never lands. Each check names what it protects, and the battery is fast enough that nobody bypasses it to keep moving.
  • Verification gate commitP22E021 — Every commit states what was verified and what was not, and the statement is true. The battery is measured before it is extended: a check that cannot fail is removed or fixed, never trusted. The gate runs on the commit, because there is no publish — editing is publishing, and the commit is the only moment where "this version is the true one" can be said.

  • Drawing As RepoP22E005 — Drawing is versioned work: a file has a defined place in the repository, and git becomes the memory of the drawing. Commit granularity carries meaning, a branch holds an alternative story, and HEAD exports on its own. Collaboration follows git, and the chosen approach says why it is git-native rather than version-control-native.
  • Consumer EraP22E006 — The consumer era is closed. Epics that existed to use CSP and Krita as the user's own tools stop being work. What survives is competitor knowledge, and that is collected only when there is a feature to compare against. Retiring is removing from the path, not deleting the record.
  • Line Or BrushP22E010 — The drawing decides whether a stroke is a line, whose identity is the path, or a brush, whose identity is the stamp. What the file saves, what erase-to-intersection may assume, what a brush swap re-renders and what one commit per second costs in bytes all follow from that decision.
  • Gesture ContractP22E012 — The contract between gesture and body is written before any gesture is designed. The question is which conditions the body needs to incorporate the tool, and what breaks that incorporation — not which gesture looks good.
  • CSP MaterialsP22E014 — The material system of Clip Studio Paint is understood: types, formats and where each lives on disk. Assets download from Clip Studio Assets, and the whole set syncs through Syncthing to the user's phone and Mac without a manual pass.
  • Git Native DrawingP22E015 — The taxonomy of git-native illustration is written: file versus repo, HEAD against working tree, revision, branch, fork and merge, autosave against commit, and where the repository lives. The boundary of git in the browser is measured. Browser-first or app follows from the taxonomy, not from preference, and nothing is built before the discovery closes.
  • Open Drawing AppP22E016 — A drawing app built on open primitives — pointer events, InkML, a libmypaint brush engine — instead of depending on closed tools. Pen and pressure, vector ink, layers, an open format, a file that lives in a folder, a document an agent can read and modify, and a mobile surface that works.
  • Krita ComparisonP22E018 — Krita and Clip Studio Paint are compared through the lens of the user's illustration study: where Krita is better, how far its API and .kra format allow editing, what vector brushes and layers exist, whether erase-to-intersection survives, and how the two trade files.
  • Vector BrushesP22E019 — Existing vector brush engines, formats and presets are discovered and what can be reused or adapted is named. The dependency contract between document, stroke and brush is written, including swap, a missing brush and the raster thumbnail. The thesis is that a brush is a font.
  • PressureP22E020 — Pressure sensitivity is defined through its path: capture, representation, mapping, then render or edit. Each contender's promise is compared with what it delivers, and the approach for the web vector MVP follows from the comparison. Input and mapping live here; the brush engine lives in its own epic.

In the same way that a well-designed object reveals how it wants to be held, this product reveals how it wants to be used before anyone reads a word. That is the whole ambition: cognition that shows itself in the surface.

What it is

It began as an internal instrument and stayed one. The shape came from use, not from specification — every part that survived is a part someone reached for more than once. What follows is a description of that shape.

How it works

Three movements, in order. First the intake, where material arrives unformed. Then the reduction, where it is made small enough to hold. Finally the return, where it goes back out into the same world that produced it.

flowchart LR
  A[intake] --> B[reduction]
  B --> C{holds?}
  C -->|yes| D[return]
  C -->|no| B

Status

Working, with the usual caveats. Nothing here asks for attention it has not earned, and nothing claims to be finished.
