Monitoring that presents itself. Watches projects, says what it sees.

Currently workingActive epics

  • Reviews CorpusP00E003 — The agent governs a second corpus under the librarian-grounding doctrine: an archive of NON-BOOK sources such as transcripts, articles and posts. Reviews drawn from that corpus are grounded against what the archive actually holds, so a claim never cites material that is absent. Each review names the source it came from and the archive entry that supports it. Portuguese-language inputs are accepted; the governing contract is English.
  • Weekly CalculationsP00E004 — The weekly report's module calculations are correct and stable. Token costs render without the wonky numbers that the earlier build produced, and the balance module shows OpenRouter and DeepSeek as plain lines inside Token Costs. A thin paid balance raises a subtle mark, never a top banner. The report still renders when a balance capture fails, and the failure is visible rather than silent.
  • Meetings CorpusP00E005 — Meetings exist as their own product with a corpus kept separate from Reviews. The corpus holds transcripts and their metadata, and a skill lets the owner find, browse and add to it. Transcription itself is a shared horizontal capability owned elsewhere; this product consumes it and never duplicates it. Portuguese-language meeting content is preserved verbatim.
  • Transcription CapabilityP00E006 — Transcription exists as a horizontal capability that any product consumes, not as a report module. Audio is captured, transcribed and stored once, and the result is available to every consumer that needs it. The capability owns the engine and its runtime; products own what they do with the text. Nothing in the report pipeline depends on it directly, so the two can evolve apart.
  • Tooling Access AuditP00E009 — The agent's access to the ecosystem's skills, MCP servers and tools is fully audited and documented. An inventory exists, an access matrix records what is reachable and what is blocked, and the gaps that limit capability are named with a suggestion for each. Tooling that expands the substrate is researched and proposed, never installed without a decision. The audit is repeatable, so a later run can show what changed.
  • Librarian GroundingP00E015 — Every report that makes a claim is grounded against the current book archive before it ships. The Librarian answers what the corpus contains and which book entry matches, and the report confronts each claim with that answer. A claim with no support in the archive is marked as such, not smoothed over. When the archive is unavailable the gap is stated plainly rather than assumed away.
  • Modular SubstrateP00E018 — The worker runs on a filesystem-based event log with append-only temporal semantics. Multiple writers add to the substrate without a lock, and readers compose a view at query time instead of relying on a materialized state. History is never rewritten, so any past view can be reconstructed exactly. Governance is minimal by design; the substrate carries the structure, not ceremony.
  • FOSS Provider ReviewP00E021 — A review of open-source projects establishes which parts of a provider-offer normalization strategy are commodity and reusable, and which gap requires the organization's own work. The question is what can be composed, and what is the smallest proprietary layer that preserves the strategy. Candidates are named with their licence, hosting posture and fit. The review informs the provider-routing decision; it does not implement it.
  • Omnivore InstallP00E023 — Omnivore runs self-hosted on the local machine through a container runtime, with the Instapaper archive imported for unread items only and the data cleaned before use. Android and Mac clients are documented so the owner can read from either. The epic ends at the install and import boundary; artificial intelligence over the corpus lives elsewhere. Phases are set by the owner, not by convenience.
  • Transcript StorageP00E026 — A corpus of meeting transcripts exists with storage and retrieval, and a skill teaches how to find an entry, navigate its frontmatter, and add a new transcript from whatever transcription system a contributor uses. The capture and speech-to-text engine lives in a separate epic, so the corpus is not tied to one motor. Scope is deliberately narrow: storage and retrieval, nothing else.

Coming soonPlanning epics

  • Radar DiscoveryP00E017 — A prospective intelligence layer watches NocoDB, Reddit and Feedly for signals that are worth the owner's attention. Provenance is preserved as the source of truth: every entry carries its origin, so a later reader can verify it. The layer signals and presents; it does not decide, route, or act on what it finds. Signals that stop mattering decay instead of accumulating forever.
  • Reading MemoryP00E020 — The system remembers what the owner has read, not only what the corpus contains. A reading record captures what was read, when, and what the owner thought of it, and it lives beside the sourcing record rather than replacing it. Consumption data is governed here; sourcing stays with the Librarian, which answers corpus and match questions on request. Queries can tell the two apart without confusion.
  • Notification ProtocolP00E022 — One protocol defines how and when anything in the fleet notifies a human. Channels, severity and quiet rules are stated once, so an agent does not invent its own notification behavior. A notification carries what happened and where to look, and it never duplicates a report the owner can read directly. Alerts that fire too often are a defect in the protocol, not noise to tolerate.
  • Omnivore AIP00E024 — Ideas for intelligence over the read-it-later corpus are discussed here: routing through the local model runtime, extending Reviews, and hooks that new saves could trigger. The owner sets the agenda, and nothing is implemented without an explicit request. The epic is a discussion record, so a later reader can see which ideas were raised, which were dropped, and why. It holds no running code.
  • Health List ModuleP00E042 — The weekly report consumes the health artifact that infrastructure publishes and renders it as a module. The module reads the current file, shows what is unhealthy in plain language, and does not reproduce the check itself. A missing or unreadable artifact is stated as a gap rather than rendered as a healthy system. Format changes are negotiated with the producing side.

In the same way that a well-designed object reveals how it wants to be held, this product reveals how it wants to be used before anyone reads a word. That is the whole ambition: cognition that shows itself in the surface.

What it is

It began as an internal instrument and stayed one. The shape came from use, not from specification — every part that survived is a part someone reached for more than once. What follows is a description of that shape.

How it works

Three movements, in order. First the intake, where material arrives unformed. Then the reduction, where it is made small enough to hold. Finally the return, where it goes back out into the same world that produced it.

flowchart LR
  A[intake] --> B[reduction]
  B --> C{holds?}
  C -->|yes| D[return]
  C -->|no| B

Status

Working, with the usual caveats. Nothing here asks for attention it has not earned, and nothing claims to be finished.
